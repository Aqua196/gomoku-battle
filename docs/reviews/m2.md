## 问题清单（按严重度排序）

---

### M2-R1 — [major] `game_over{winner:null, reason:"disconnect_timeout"}` 违反 PROTOCOL §3 不变量「winner:null 仅当 draw」

- **位置**：`backend/internal/game/actor.go:374-379`（`onAbandonTimeout` → `finish(Empty, ReasonDisconnectTimeout)`）；`frontend/src/pages/Game.tsx:209-214`（`winner===null → '平局'`）
- **描述**：双方同时断线且都不在 `AbandonTTL`（prod 10min）内重连时，终局帧为 `reason:"disconnect_timeout", winner:null`。§3 明文 `winner:null 仅当 reason:"draw"` —— 冻结契约被破坏；前端按 `winner===null` 判平局，把「双方弃局」渲染成「平局」。
- **触发条件/复现**：双人对局中两人同时掉线（或同端两 conn 都 close），都超过 10min 不归 → `onAbandonTimeout` 产出上述帧。广播落在死 conn 上客户端看不到，但 wire 契约与任何下游消费方（metrics/未来持久化/复盘）都会误读；若任一方恰好在 abandon 前极短窗重连又走，理论上也会看到错误的「平局」。
- **修复建议**：三选一——(a) 新增 `reason:"abandoned"` 并让前端 map 独立文案（需动 PROTOCOL.md，走架构 agent）；(b) 明确 §3 扩写「winner:null 允许 draw|abandoned」；(c) 按裁决规则判一胜负（不推荐）。

### M2-R2 — [major] 双断线后归者收不到 presence 帧 + reducer 不同步 `game_state` 内的在线状态 → 全程错误「对手断线」UI

- **位置**：`backend/internal/game/actor.go:326-340`（`applyReconnect` 只向对手发 `presence{connected:true}`；对手仍离线才向回归者发 `presence{false}`）；`frontend/src/state/store.tsx:198-212`（`game_state` case 不更新 `opponentConnected`/`opponentDeadline`）
- **描述**：双方都在线的对局中 A、B 先后断线（双离线，判负挂起）。A 先重连——A 收到 `game_state` + `presence{false,B-deadline}`，视图正确。B 后重连——B 只收到 `game_state`（其中 `players.*.connected=true`），**没有任何 presence 帧**。B 的 `opponentConnected` 保持 A 断线时写入的 `false`、`opponentDeadline` 保持 A 的旧 deadline（多半已过期→倒计时钉在 0s）。结果：B 的横幅「对手断线，0s 内不回判负」+ 对手卡片「断线」持续到对局结束，永不自愈。
- **触发条件/复现（已实测）**：探针 PB2——A close→B close→A 以 token 重连→B 以 token 重连。B 侧收集到的全部帧里**无 `opponent_presence`**，仅 `game_state`。
- **修复建议**：任一侧修补即可闭环——(a) 服务端：`applyReconnect` 无论对手在线与否都向回归者补发一条 `opponent_presence`（回归者的视图权威化）；(b) 前端：`game_state`/`game_over` case 用 `game.players[opp].connected` 同步 `opponentConnected`、用 `game.reconnectDeadline` 同步 `opponentDeadline`。建议两侧都做（客户端本就该把 game_state 当权威快照）。

### M2-R3 — [minor] 引擎 `e.stop` 死代码：超时截断语义与实现不符

- **位置**：`backend/internal/ai/engine.go:43,63,99-109,113,131,146-148,168-170`
- **描述**：`stop` 仅在 `Move` 开头被置 false，**全代码无任何位置置 true**——`rootSearch`/`search` 中所有 `if e.stop` 分支均不可达；注释宣称「ok=false when the deadline aborted the iteration」实际永不返回 false（hard 的迭代循环里 `mok` 恒真，被截断迭代的"半成品"结果照样覆盖 `best`，与文档语义「保留上一个完整迭代的答案」不符）。deadline 实际只靠 `expired()` 的 `time.Now()` 检查兜底：过期后每个剩余 root 候选仍各付一次全量 `evalFor`（实测 70 子中盘 overshoot ≤0.5ms，有界但浪费）。
- **修复建议**：要么补 `e.stop=true` 于 deadline 检查处（真截断当前迭代并丢弃其结果），要么删 flag 并把注释改成实际语义。

### M2-R4 — [minor] `Driver.Notify` 在 inbox 满时丢弃的是**最新**状态（与注释相反）

- **位置**：`backend/internal/ai/driver.go:28-29,54-64`
- **描述**：cap-1 inbox，`select{case inbox<-gs: default:}` 满了就丢**新**帧——保留的是**最旧**AI 回合状态，与注释「only the newest state is queued」正好相反。当前接线不可达（AI 回合态不可能在 driver 消费前排起两帧——轮到 AI 前必须先有真人落子，而消费后会立即独占思考），但注释承诺的语义若被复用（AI 执黑/双 AI）即成隐患。
- **修复建议**：满时先 drain 再塞新值（`select{case <-inbox: default:}` 后 send），或换 `atomic.Pointer` 存最新快照。

### M2-R5 — [minor] 对局终止不打断 AI 思考：每次被终止的对局白烧至多一个 think 预算

- **位置**：`backend/internal/ai/driver.go:89-92`（`eng.Move` 期间不查 `done`）
- **描述**：真人 resign/timeout/断线判负发生在 AI 思考中时，引擎把当前 `think`（hard=1.8s）跑完、把招法投给已死 actor（被 done 分支丢弃）后 driver 才退出。PC 实测：resign 于 5s 思考中 → driver 活满预算才退。语义安全，纯浪费。
- **修复建议**：`eng.Move` 传入可取消的 deadline，或引擎循环里 select done。

### M2-R6 — [minor] 断线恰逢己方回合：判负理由在 `timeout` 与 `disconnect_timeout` 间不确定

- **位置**：`backend/internal/game/actor.go:345-371`；PROTOCOL §5「断线时若轮到断线方，turnDeadline 照常走」
- **描述**：断线者的 `turnDeadline`（30s）与 `reconnectDeadline`（30s）等长并行——若断线恰逢己方回合，先到的计时器决定 game_over 理由是 `timeout` 还是 `disconnect_timeout`。同一行为两种理由，对玩家提示与统计口径不一致（spec 字面允许，但验收/文案应预期双理由）。
- **修复建议**：要么接受并写进 DECISIONS/文案；要么断线时暂停该方 turnDeadline（改规则需动契约）。

### M2-R7 — [minor] `Hub.Hello` 的 `code` 返回已成死参数；`unauthorized` 永不可达

- **位置**：`backend/internal/hub/handlers.go:66-110`（所有分支 `return ..., ""`）；`backend/internal/ws/server.go:180-184`（`if code != ""` 死分支）
- **描述**：takeover（R2 修复）落地后 Hello 不再有任何错误返回，server 侧检查与 §8 的 `unauthorized` 错误码成为不可达残留。
- **修复建议**：收掉 code 返回值简化签名；§8 若保留该码须注明「保留未用」或删除。

### M2-R8 — [minor] `aiBadgeLabel` 从 AI 昵称 `AI (hard)` 正则抠难度——与服务端命名约定字符串耦合

- **位置**：`frontend/src/state/ai.ts:33-42`；服务端命名 `handlers.go:311`
- **描述**：难度徽标不靠字段而靠解析服务端拼的 nick。改名（如「AI·困难」或本地化）徽标静默退化为原文。有兜底故影响小。
- **修复建议**：`GamePlayer`/`RoomPlayer` 加 `difficulty` 字段（契约扩展）或至少给 nick 约定写进 DECISIONS。

### M2-R9 — [minor] `isAiThinking` 把「非我回合」等同「AI 思考中」

- **位置**：`frontend/src/state/ai.ts:49-57`；`Game.tsx:51,101-106`
- **描述**：`turn!==youColor && aiOpp` 即显示 AI 思考——多数场景正确；`youColor===null`（derive 失败的边角）落到「对手思考中」，人机房里文案仍为人人模式措辞。另外 AI 驱动卡死/超预算时同样显示「思考中」（反而诚实，勉强可接受）。
- **修复建议**：低优先；可在 youColor null 时按 aiOpp 存在性也给「AI 思考中」。

### M2-R10 — [minor] 服务端接受纯空白昵称（M1 遗留未发现）

- **位置**：`backend/internal/ws/server.go:176-179`（rune 计数 1–32，无 trim）
- **描述**：`{"type":"hello","nick":"   "}` 合法通过；前端 `connect()` 有 trim 故 UI 不可达，但裸 WS 客户端可造出展示为空的昵称。
- **修复建议**：`strings.TrimSpace` 后计数。

### M2-R11 — [minor] SPA fallback 对缺失静态资源也回 index.html（M1 遗留未发现）

- **位置**：`backend/internal/ws/server.go:89-99`
- **描述**：`/assets/missing.js` 返回 200+HTML → 浏览器按 text/html 拒绝/报错，排障时现象古怪。
- **修复建议**：仅对导航请求（无扩展名或 `Accept: text/html`）fallback；`/assets/` 下缺失直接 404。

### M2-R12 — [minor] `game_start` reducer 路径漏掉 `applyServerNow`

### M2-R13 — [minor] `AIThink` 注释引用的「PROTOCOL §8: <= 2s」在契约中不存在；play_ai 语义未回写冻结文档

- **位置**：`backend/internal/protocol/protocol.go:110-112`；`PROTOCOL.md` §2 line 54 / §8
- **描述**：§8 是错误码表，没有任何「每手 ≤2s」或 AI 座位语义条款；`play_ai` 只写了 `game_start（M2）`。冻结契约自封「唯一契约」却未收录：难度枚举的座位规则（AI 恒白/人类恒黑）、isAI 房间的行为差异、AI 思考预算上限。
- **修复建议**：架构 agent 在 PROTOCOL.md 补 §10（或并入 §2/§4）写清上述约定，并把 Config 注释改指到真实条款。

### M2-R14 — [minor] `Config.For` 未知难度返回零值配置 → 引擎退化为兜底扫描

- **位置**：`backend/internal/ai/engine.go:26-36`
- **描述**：`Config{}` 的 `Breadth=0` 令 `candidates` 被截到空，`Move` 掉到中心/首个空位兜底——仍是合法落子但静默无脑化。`PlayAI` 已校验难度故不可达，但 `For` 是包级 API，未来调用方易踩。
- **修复建议**：未知难度回退到 normal 配置或返回 error。

### M2-R15 — [minor] takeover 重连会向对手发一条「伪重连」presence

- **位置**：`backend/internal/game/actor.go:303-341`（`applyReconnect` 无条件 `send(opponent, presence{connected:true})`）
- **描述**：token 顶替（对端从未被标记断线）时，对手收到 `connected:true` 但没有过对应的 `false`——前端表现为无来由的「对手已重连」3s 横幅（顺带能治好 M2-R2 的 stale 态）。语义噪音。
- **修复建议**：仅当 `seat(c).Connected` 之前为 false 时发该帧。

### M2-R16 — [minor] 验收证据自矛盾：`ai_probe.py` 按不存在的 `lastMove.color` 计数，恒得 `ai_moves=0`

- **位置**：`docs/evidence/ai_probe.py`（`lm.get("color")`——协议 `lastMove` 只有 `{x,y}`）；`docs/evidence/m2-ai-live.txt`；`ACCEPTANCE.md` M2 表
- **描述**：实盘证据打印 `RESULT: ai_moves=0 my_moves=5` 却同帧 `winner=white reason=five`——探针计数器永远数不出 AI 手数，`sys.exit(0 if ai_moves>=3 else 1)` 必然失败；该证据在验收表中被当作通过依据记录。功能本身经本评审 PA 探针实证正常（AI 在 (7,8) 回招），是证据脚本的问题不是实现的问题——但按「证据不撒谎」标准应如实修正。
- **修复建议**：探针改为按 `moveNumber` 或 `turn` 交替计数；重跑并把正确证据写回 ACCEPTANCE。

## 结论

M2 增量设计干净：AI 复用 actor mailbox 无特权路径、driver 生命周期绑 actor.done 无泄漏、引擎落子恒合法且必杀/必防前置、非阻塞实测达标。两处 major 都在**双断线**这条冷门路径上：契约不变量被 `abandoned` 终局帧破坏（M2-R1），以及回归者 presence 缺口叠加前端不同步快照字段导致持久性错误 UI（M2-R2，已实测）。其余为死代码/文档偏差/边角，均可低成本修复。
